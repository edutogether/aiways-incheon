# 태블릿 구간(600~1023px)에서 대시보드 밖으로 나갈 길이 하나도 없다

## 문제

**실측으로 확정했다.** 프리뷰 채널(`ai-ways-incheon--pc-s5-review-5qopjkzi.web.app`)에서
`hasTouch:true, isMobile:true`로 네 크기를 쟀다 — 600×960 / 768×1024 / 900×700 / 1023×768.

| 크기 | `.site-header` | `.mobile-quick-nav` | `.scroll-cue` | 보이는 해시앵커 | 보이는 섹션 |
|---|---|---|---|---|---|
| 600×960 | 숨김 | 숨김 | 숨김 | **13개 중 0개** | `dashboard`만 (나머지 6개 `display:none`) |
| 768×1024 | 숨김 | 숨김 | 숨김 | **13개 중 0개** | 〃 |
| 900×700 | 숨김 | 숨김 | 숨김 | **13개 중 0개** | 〃 |
| 1023×768 | 숨김 | 숨김 | 숨김 | **13개 중 0개** | 〃 |

네 크기 전부 동일하다. 밖으로 나가는 길은 `data.go.kr` 외부링크("기록"),
`./mobile/index.html`(학생 앱), ↻ 새로고침 버튼 셋뿐이고, **사이트 안의 다른
섹션으로 가는 경로는 0개다.**

### 원인

`styles/cb3a.css:1511`, 다음 미디어 블록 안:

```css
@media (min-width: 37.5rem) and (max-width: 63.99rem),
       (min-width: 64rem) and (max-width: 87.4rem) and (hover: none) and (pointer: coarse) {
  .site-header, .mobile-quick-nav, .phone-shell-frame { display: none !important; }
  ...
  .scene { display: none !important; }
}
```

한 줄이 **두 내비게이션 표면을 동시에** 끈다. `.site-header`(PC 헤더 내비)와
`.mobile-quick-nav`(폰 하단 고정 바)가 같이 꺼지는데, 폰 구간에서는
`.mobile-quick-nav`가 살아 있고 PC 구간에서는 `.site-header`가 살아 있어서
**태블릿 구간만 둘 다 없는 사각지대**가 됐다. 바로 다음 줄이 `.scene`을 전부
꺼서 갈 곳 자체도 사라진다.

🔴 **이것이 실수인지 의도인지는 확정하지 못했다.** `app.md`의 "태블릿 화면"
절은 **히어로를 일부러 숨긴다**고만 적고 있고 내비게이션은 언급하지 않는다.
2×2 패널로 화면을 채우는 목표 화면에 헤더가 없었던 것은 사실이므로, 내비가
같이 꺼진 것이 그 과정의 부수효과일 가능성이 있다. **미결 질문으로 올린다.**

## 원하는 결과

폭 600~1023px(및 터치 기기 ~1398px)에서 선생님이 **대시보드에서 다른 섹션
(프로젝트·커리큘럼·갤러리·자료 등)으로 이동할 수 있다.** 지금은 주소창에 해시를
직접 치는 것 말고는 방법이 없다.

## 영향받는 사용자·시스템

- **실사용자 영향 있음.** 파일럿 4개 학교 담임교사가 학교 보급 태블릿(600×960
  소형 안드로이드)이나 아이패드로 대시보드를 열면 그 화면에 갇힌다. 아이패드
  가로(1180~1366px)도 `(hover:none) and (pointer:coarse)`로 이 구간에 들어온다.
- 건드리는 곳은 `styles/cb3a.css` 한 파일이지만, 🔴 **PC 화면 CSS는 Bumm님이
  직접 관리하는 영역**이라(`app.md`) 세션이 임의로 바꾸지 않는다.
- 전환본(`pc-app/`)은 CSS를 바이트 그대로 복사하므로 원본을 고치면 전환본도
  같이 따라온다 — 두 곳을 따로 고칠 필요는 없다.

## 제약

- **S5(PC 리액트 전환)와 섞지 않는다.** S5가 끝난 뒤 별건으로 한다 — 같은
  변경에서 CSS까지 손대면 화면 차이가 났을 때 전환 탓인지 CSS 탓인지 못 가린다.
- **2×2 패널 구성을 깨지 않는다.** `app.md`가 못박은 "모든 크기에서 예외 없이
  지켜야 하는 것": 2×2 유지 · 패널 밖으로 넘치는 요소 0 · 도넛 1.000 · 배경
  동일 · 눌려서 세로로 쪼개진 글자 없음.
- **폰 구간(짧은 변 599 이하)과 PC 구간(1024+, 마우스)의 화면을 건드리지 않는다.**
- 고친 뒤에는 위 네 크기를 **같은 방식으로 다시 재서** 표를 채운다. "안 겹친다"가
  아니라 "실제로 이동이 되는가"로 판정한다.

## 선택지 — 🔴 세션이 고르지 않는다

셋 다 **화면 모양이 달라지는 선택**이라 Bumm님이 정하실 일이다. 2×2에 미치는
영향을 같이 적는다.

| | 무엇 | 2×2 화면에 미치는 영향 | 비고 |
|---|---|---|---|
| **A** | 태블릿 구간에서 `.site-header`를 되살린다 | 🔴 **세로가 79~112px 줄어든다.** 2×2가 화면을 채우는 구조라 패널 비가 그만큼 납작해진다(세로 태블릿 0.730 → 더 낮아짐). `app.md`가 "히어로를 일부러 숨긴다"고 한 취지와도 어긋나 보인다 | 가장 간단하지만 목표 화면에서 가장 멀다 |
| **B** | `.mobile-quick-nav`(하단 고정 바)를 태블릿 구간에도 살린다 | `position:fixed`라 **문서 흐름을 안 밀지만** 화면 아래를 덮는다. 폰 구간에서 이미 쓰는 것이라 새 디자인이 아니고, 링크가 3개(대시보드·랭킹·매립지)라 좁다 | 지금 CSS에 이미 규칙이 있어 `display:none`만 풀면 된다. 다만 **덮이는 만큼 패널 높이를 줄여야** 넘침이 안 생긴다 |
| **C** | 대시보드 안(2×2 위/아래)에 섹션 이동을 넣는다 | 2×2가 쓸 수 있는 높이가 줄어든다. 넣는 자리·모양을 새로 정해야 한다 | 목표 화면을 가장 덜 해치게 만들 수 있지만 **새 디자인이 필요하다** |

셋 다 `.scene { display:none !important }`도 같이 풀어야 갈 곳이 생긴다 — 그
줄이 태블릿에서 대시보드 외 섹션을 통째로 끄고 있다. **어느 섹션까지 보여줄지도
결정 사항이다**(전부인지, 일부인지).

## 미결 질문

- **태블릿에서 내비가 꺼진 것은 의도인가, 히어로를 숨기는 과정의 부수효과인가?**
  `app.md`는 히어로만 언급하고 내비는 언급하지 않는다. 의도였다면 이 intent는
  `dropped`가 맞다.
- **태블릿에서 대시보드 말고 어느 섹션까지 보여줄 것인가?** 지금은 6개가 전부
  `display:none`이다. 전부 여는 것과 일부만 여는 것은 다른 작업이다.
- **A/B/C 중 무엇으로 갈 것인가?** 셋 다 화면 모양이 달라진다.
