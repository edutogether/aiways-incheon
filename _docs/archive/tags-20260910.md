## 2단계에서 할 것 (확인 후)

```
git update-ref refs/archive/tags/<이름> <커밋>
git tag -d <이름>
git push origin :refs/tags/<이름>
git push origin refs/archive/tags/<이름>
```

⚠️ `.githooks/pre-push`가 freeze 태그 삭제를 막는다. **훅은 지우지도 고치지도
않는다** — 이 작업에 한해 `--no-verify`를 쓰고, **썼다는 사실을 보고에 밝힌다.**
훅은 그대로 남아 앞으로도 실수로 지우는 것을 계속 막는다.

## 2단계 실행 결과 (2026-09-10 완료)

**18개를 옮겼고, 남은 태그는 셋이다** — `aiways-freeze-20260910-pre-pc-conversion`,
`aiways-freeze-20260910-pre-tablet-fix`, `mobile-react-freeze-20260909`.
로컬 `git tag`와 `git ls-remote origin refs/tags/*` 양쪽에서 확인했다.

**순서를 지켰다: 만들고 → 올리고 → 그 다음에 지웠다.** `refs/archive/tags/`를 먼저
만들어 origin에 밀어 18개가 원격에 다 있는 것을 확인한 뒤에야 태그를 지웠다. 반대
순서였으면 push가 한 번 실패하는 것만으로 지점이 사라진다.

**주석 태그 객체를 그대로 옮겼다.** 커밋이 아니라 태그 객체를 가리키게 했으므로
`git show refs/archive/tags/<이름>`에 **태그 메시지가 그대로 나온다** — 검토 결과가
메시지에 들어 있는 태그(`mobile-freeze-20260812` 등)의 내용이 보존됐다는 뜻이다.
18개 중 13개가 주석 태그, 5개가 커밋을 직접 가리키던 경량 태그다(origin의
`refs/archive/tags/*`가 31줄 = 18 + 주석 13개의 `^{}`).

**되돌아갈 수 있는지 실제로 해봤다.** `pc-glass-redesign-freeze-20260819`을 골라
`git checkout refs/archive/tags/pc-glass-redesign-freeze-20260819` → 커밋 `5f681c5`
(그 시점 `index.html` 606줄)에 도착하는 것을 확인하고 `main`으로 돌아왔다.
"옮겼으니 괜찮을 것"이 아니라 한 개를 실제로 열어 본 결과다.

**`git update-ref` 반복이 한 개를 조용히 건너뛰었다.** 만든 개수를 세어 보니
17개라 `comm`으로 목록을 대조해 빠진 하나를 찾아 다시 만들었다. 개수를 안 셌으면
그 지점 하나만 사라진 채로 끝났을 것이다 — 반복 작업은 **결과 개수를 세야 한다.**

🔴 **`--no-verify`를 썼다.** 태그 삭제(`git push origin :refs/tags/<이름>`) 한 종류에만
썼고, `.githooks/pre-push`는 **읽지도 고치지도 지우지도 않았다.** 훅은 그대로 살아
있어 앞으로도 freeze 태그의 실수 삭제를 계속 막는다.
