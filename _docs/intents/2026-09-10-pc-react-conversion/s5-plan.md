# S5 계획 — 라이브 `index.html`을 전환본으로 바꾼다

작성 2026-09-10. **아직 실행하지 않았다.** 이 전환에서 되돌리기가 제일 무거운
자리라, 무엇을 바꾸고 어떻게 되돌리는지를 먼저 적는다.

🔴 **이 계획의 승인 조건은 아래 5절(Bumm님 직접 확인)이다. 그 확인 없이는
S5를 배포하지 않는다.**

## 1. 무엇이 바뀌는가

| 지금 | S5 이후 |
|---|---|
| 루트 `index.html` = 손으로 쓴 **803줄** (라이브) | `pc-app` 빌드 산출물 (지금 `pc-next/index.html` **96줄** + 주입 태그) |
| 산출물이 `pc-next/`(gitignore) | 산출물이 **저장소 루트** |
| `pc-app/src/App.tsx`는 전환 중인 사본 | **App.tsx가 화면의 source of truth** |

바꿔야 하는 곳:

- **`pc-app/vite.config.ts`** — `OUT_DIR`을 루트로. 🔴 **동시에
  `VERBATIM_STYLESHEETS`·`LEGACY_FILES` 복사를 끈다.** 그때는 원본이 이미 그
  자리에 있어 **제 자신을 제 자신으로 덮어쓰게** 된다(파일에 이미 주석으로 적혀
  있다).
- **`.gitignore`** — `mobile/`과 같은 방식으로 루트 `index.html`을 뺀다.
  🔴 **다만 `mobile/`은 폴더 하나였고 이번은 사이트 루트 파일이다.** 잘못되면
  `stageHostingSite.js`의 `REQUIRED`가 멈춰 세우긴 하지만, 그 장치에 기대기
  전에 CI에서 반드시 빌드되게 하는 것이 먼저다.
- **`.github/workflows/deploy.yml`의 `deploy-hosting`** — 지금은 `mobile-app`만
  빌드한다. **`pc-app` 빌드 단계를 더한다.** 이것을 빠뜨리면
  `stageHostingSite.js`가 "index.html이 없습니다"로 멈춘다(조용히 빈 사이트가
  나가지는 않는다 — 그 장치는 이미 있다).
- **`pc-frontend` job을 `deploy-hosting`의 `needs`에 넣는다.** 지금은 산출물이
  배포에 안 들어가 일부러 뺐다. S5부터는 넣지 않으면 **전환본 검사가 실패해도
  배포가 나간다.**

## 2. 바꾸기 전에 — 프리즈 태그와 되돌리기 예행연습

`aiways-freeze-20260910-pre-s5`를 찍는다. §23-6 순서 그대로:

```
git tag -a aiways-freeze-20260910-pre-s5 -m "PC 리액트 전환 S5(라이브 교체) 직전"
git push origin aiways-freeze-20260910-pre-s5
git ls-remote origin refs/tags/aiways-freeze-20260910-pre-s5   # ← 되읽어 확인
```

🔴 **찍고 끝내지 않는다. 되돌리는 명령을 실제로 실행해 차이 0건을 확인한다.**

```
git checkout aiways-freeze-20260910-pre-s5 -- index.html
git diff --stat        # 아무것도 안 나와야 한다
```

**§21-14** — 되돌리기 자체가 성공했는지를 먼저 본다. 오늘 `git stash`가 조용히
아무것도 안 한 적이 있다.

## 3. 되돌리는 절차 — 사고가 나면 몇 분

**가장 빠른 층(정적 파일만 깨진 경우, 1~2분):**

```
firebase hosting:clone ai-ways-incheon:<이전_버전ID> ai-ways-incheon:live --project ai-ways-incheon
```

🔴 **그다음 반드시 `node scripts/postDeploySmoke.js`** — 코드가 아니라 라이브
응답을 보는 유일한 층이다.

**정석(코드까지 되돌릴 때):** `git revert <S5 커밋>` → push → CI 재실행.
🔴 **로컬에서 `firebase deploy`로 되돌리지 않는다.** 윈도우 로컬은 CRLF, CI는
LF라 내용이 같아도 바이트가 다르다(app.md에 기록된 실제 사고). 오늘
`.gitattributes`로 스타일시트·스냅샷은 고정했지만 **`index.html`은 아직
아니다** — S5에서 그것도 고정 대상에 넣는다.

**이번 S5는 프론트만 바꾸므로 Functions·rules는 되돌릴 것이 없다.** 한쪽만
되돌리는 것이 안전한 드문 경우다.

## 4. 배포 후 — "성공했다"가 아니라 "라이브가 그것인가" (§21-12)

배포 job이 초록불인 것과 라이브가 그 커밋인 것은 다르다. 셋을 본다:

1. `gh run list --branch main --limit 1` 이 **`success`** (push 직후가 아니라 끝난 뒤)
2. 라이브 `index.html`을 받아 **번들 파일명이 바뀌었는지** 확인 —
   `curl -s https://incheon.edutogether.kr/ | grep -o 'bundle/index-[^"]*'`.
   해시 파일명이라 **안 바뀌었으면 옛 배포가 그대로다.**
3. `node scripts/postDeploySmoke.js` — **두 주소 모두**(정식 주소와 대비용
   `web.app`). 대비용이 정작 필요할 때 안 되면 대비가 아니다.

## 5. 🔴 Bumm님이 직접 눌러 확인하셔야 하는 다섯 가지 — **이것이 배포 조건이다**

기준선은 **여는 것까지만** 담고 그 안에서 실제로 도는 상태는 담지 못한다.
자동화 브라우저가 App Check를 통과하지 못하기 때문이고(reCAPTCHA가 자동화를
거부한다), 이것은 설정 문제가 아니라 **자동화의 한계**다.

| # | 확인할 것 | 안 되면 보이는 증상 |
|---|---|---|
| 1 | 학교 선택 모달의 **학교 검색** | 이름을 쳐도 목록이 안 뜬다 |
| 2 | **학년·반 바꾸기** 후 숫자가 따라오는가 | 바꿔도 예전 반 숫자가 남는다 |
| 3 | **AI 판단 모달** — 사진을 넣고 판정까지 | 분석 중에서 안 넘어간다 |
| 4 | **랭킹 모달**의 데이터 로드 | 열리는데 비어 있다 |
| 5 | **반응형 내비** 열림 상태(창을 좁혀서) | 메뉴가 안 열리거나 닫히지 않는다 |

**확인은 `pc-next/`(전환본)로 하시고, 배포 전에 한다.** 🔴 **배포 후에
발견하면 되돌려야 한다.** 이 다섯 중 하나라도 안 되면 S5를 미룬다.

팀장 세션이 시점을 잡는다.

## 7. 🔴 S5 이후에는 **비교 대상이 사라진다** — 이것이 이 단계의 진짜 위험이다

지금 대조는 전부 **"원본과 전환본을 나란히 열어 비교"**하는 구조다
(`pcSectionParity`, `pcLegacyBoot`의 원본 쪽). **S5에서 루트 `index.html`이
전환본이 되는 순간 원본은 작업 트리에 없다.** 남는 것은 프리즈 태그뿐이다.

그래서 S5의 순서는 이렇다:

1. **바꾸기 전에** `AIWAYS_PC_TARGET=pc-next`로 **기준선 전체를 통과시킨다.**
   네 폭 × 일곱 섹션의 좌표·계산된 스타일·모션 명세·스크린샷이 **전환 전에 찍힌
   스냅샷과 같아야 한다.** 🔴 **이것이 S5의 합격 판정이고, 스냅샷을 다시 찍지
   않는다**(§21-7 — 비교 대상이 자기가 만든 것이면 검사가 아니다).
2. 그것이 통과한 **뒤에** 파일을 옮긴다.
3. 옮긴 뒤 `pcSectionParity`와 `pcLegacyBoot`의 원본 쪽은 **프리즈 태그의
   `index.html`을 꺼내 비교하도록 바꾸거나, 역할이 끝났음을 적고 지운다.**
   🔴 **조용히 통과하게 두지 않는다** — 원본을 못 찾으면 건너뛰는 검사가 되면
   그때부터 아무것도 지키지 않는다(§21).

## 7-1. 🔴 합격 판정을 **미리 돌려 봤다** — 지금 3/4 통과, 남은 하나는 기준선 쪽 문제다

계획만 적지 않고 `AIWAYS_PC_TARGET=pc-next`로 실제로 돌렸다. **그 자리에서 결함
넷이 나왔고 셋을 고쳤다.**

**처음 결과: 네 폭 전부 실패.** 원인은 하나씩 달랐다.

1. 🔴 **`responsiveNavigation.js`가 아무것도 안 하고 있었다.** `app.js`와 **같은
   문제**다 — 실행되는 순간 `.site-header`를 찾는데 전환본에서는 그때 화면이
   없어서 `if (!header || !nav) return`에 걸려 **조용히 끝난다.** 반응형 메뉴
   버튼이 아예 안 생겼다(기준선에서 `responsive-main-nav`가 빠진 것으로 드러남).
   → S4와 같은 방식으로 진입점을 내놓고 리액트가 부르게 고쳤다.

2. 🔴 **`deviceTier.js`도 같은 상태였다.** `#phoneShellFrame`을 못 찾아 조용히
   끝난다 — 즉 **폰으로 들어온 학생이 학생 앱으로 안 넘어가고 PC 대시보드를
   받는다.** 🔴 **기준선으로는 이것을 영원히 못 잡는다**: 재는 네 폭이 전부 짧은
   변 600 이상이라 어느 폭에서도 이 코드가 화면을 바꾸지 않는다. 고쳤다.

3. 🔴 **`base-data-seed.tsv`와 `assets/`가 산출물에 없어 404였다.** 그런데
   **숫자만 보면 정상으로 보였다** — 시드가 없으면 `app.js`가 내장 기본값으로
   떨어지는데 그 값이 시드와 **우연히 같다**(3학년 72+64+78 = 214). 앞선 S4
   검사에서 `[data-school-observed]`가 `214`인 것을 보고 "채워졌다"고 읽었는데,
   실은 **시드를 못 받은 채 기본값이 나온 것**이었다. 복사 대상에 넣어 고쳤다.

**고친 뒤: 네 폭 중 셋 통과.** 두 번 연속 같은 결과다(흔들리지 않는다).

**남은 하나(768×1024)는 전환본 문제가 아니다.** 다른 것은 딱 둘뿐이다:

| | 기준선 | 전환본 |
|---|---|---|
| `#bootSplash` | `display: grid` (화면 가득) | `none` |
| `#dashboardToastHost` | 0×0 | 372×44 |

**기준선이 원본의 "부팅 중간"을 찍은 것이다.** 원본도 조금 더 두면 같은 상태에
도달한다 — 원본을 직접 열어 재 보니 스플래시가 `none`이 되고 **같은 토스트**
("대시보드 갱신에 문제가 생겼어요")가 뜬다. 그 토스트는 자동화 브라우저가 App
Check를 통과하지 못해서 나는 것이고 **원본·전환본 양쪽에 똑같이** 난다.

🔴 **그래서 이 한 폭은 지금 상태로는 합격 판정에 쓸 수 없다.** 두 갈래가 있고
**어느 쪽인지는 세션이 정할 일이 아니다**:

- **(가) 기준선을 다시 찍는다** — 하네스가 "부팅이 끝났는가"(스플래시가 걷혔는가)를
  기다리게 하고, **원본에서** 다시 캡처한다. 🔴 **반드시 원본에서 찍어야 한다.**
  전환본에서 찍으면 비교 대상이 자기가 만든 것이 되어 검사가 아니게 된다(§21-7).
  원본은 S5 전까지, 그리고 프리즈 태그에 남는다.
- **(나) 그대로 두고 이 한 폭의 두 항목을 예외로 적는다** — 다시 찍는 행위 자체가
  결함을 기준선에 굳힐 위험이 있으므로, 차이의 정체가 확실한 지금은 이것도 정당하다.

**추천은 (가)다.** 차이의 원인이 "화면이 다르다"가 아니라 "재는 순간이 다르다"로
밝혀졌고, 그 상태의 기준선은 앞으로도 계속 이 자리에서 빨간불을 낸다. 다만
**다시 찍는 것은 승인받고 한다.**

## 8. 이미 확인해 둔 것

- **CSP 인라인 스크립트 해시가 맞는다.** 부트 스플래시의 인라인 스크립트가
  전환본에서도 **바이트 그대로**라 `firebase.json`의
  `sha256-VlEoLly6nrCHzZ9yYflROMKgub24XbiNQsMtiOmmxK8=`가 그대로 통한다(실측).
  한 글자만 달랐어도 **브라우저가 조용히 막고** CI에서는 안 보였을 것이다.
  인라인 `<style>`은 `style-src`가 `'unsafe-inline'`이라 무관하다.
- **`pcReactBoot.js`와 번들은 `script-src 'self'`로 이미 허용된다.**
- **고전 스크립트 열 개가 산출물에 실제로 실린다**(S4에서 404였던 것을 고쳤다).
